# Kernel MCP server: what we hit while building kernel-browser

Hosted server `https://mcp.onkernel.com/mcp`, used from Claude Code 2.1.306 with a Bearer key, 2026-10-22. "Live" means seen in a real call (the row id points into [verified-facts.md](verified-facts.md)); "source" means read in the open-source server (`kernel/kernel-mcp-server` at commit 5c0e58b) and not run. Each item was also sent to Kernel through the server's own `submit_feedback` / `get_more_tools` tools, without ids, URLs or account data.

| # | Tool | What happens | Evidence | Why it matters | Suggested fix |
|---|---|---|---|---|---|
| F1 | `manage_vault_credentials` | `connect_account` with `provider: "1password"` returns only `404 not found [code: not_found]` | live (KB11): in the same vault, `manage_vault_items list` and a `provider: "kernel"` credential worked | An agent cannot tell "feature not enabled for this org" from "wrong vault or key" and may retry or recreate items | Return a clear "1Password brokered approval is not enabled for this organization" error, or hide the 1Password path when it is not available |
| F2 | `computer_action` | A `screenshot` on a default headful browser printed "could not determine viewport dimensions. use manage_browsers with action 'get' ..." and still returned the image | live (KB5) | Agents treat the message as a failure and spend a call on `get` | Only warn when the screenshot actually fails, or read the viewport from the session |
| F3 | `manage_browsers` | `create` returns the raw browser object, so `cdp_ws_url`, `webdriver_ws_url` and `base_url` reach the model; `list` strips `cdp_ws_url` only; the `kernel://.../browsers` resource strips nothing | live (KB2, create) and source (`browsers.ts:946`, `resource-templates.ts:80-92`) | These URLs let anyone holding them drive the browser; they land in transcripts and logs. The MCP tools never need them | Strip all three from every tool result and resource, as `browser_pools acquire` already does |
| F4 | `manage_profiles` | `setup` starts a browser with a fixed 300 s timeout and no tags, takes no `timeout_seconds`, `tags` or `name`, and never checks that the user finished; its next action tells the model to delete the browser "when done" | source (`profiles.ts:194-209`) | The model cannot find or clean up setup browsers by tag, and a delete before the user finished saves a logged-out profile | Accept `tags`, `name`, `timeout_seconds`; return a check the model can poll (for example "is a signed-in element present") or document that deleting early saves the current state |
| F5 | `manage_credentials`, `manage_auth_connections` | `values`, `totp_secret` and `submit` `field_values` take passwords, TOTP seeds and codes as tool input with no warning, while the vault tools say "never ask for passwords or totp seeds in chat" | source (`credentials.ts:53-69`, `auth-connections.ts:230-243`) | Tool input is stored in the client transcript. Models fill these fields with secrets the user pasted | Add the same warning to these descriptions, or route secret entry through the hosted page only |
| F6 | `browser_repl` | `timeout_sec` is capped at 150 | source (`browser-repl.ts:19`); the REPL docs say "up to 300" | A model following the docs gets a schema error | Align the cap and the docs |
| F7 | `manage_auth_connections` | A stored-credential `login` failed once with `provider_unavailable` ("The sign-in service's model providers were temporarily unavailable"); the next `login` succeeded | live (KB6), single observation | Fine as a transient, but `can_reauth_reason` stayed `no_prior_successful_login` with no hint that a plain retry is the fix | Mark `provider_unavailable` as retryable in the error and in the `wait` instruction |
| F8 | docs (Playwright execution, REPL, standby) | The docs say that after a timeout "the executor keeps its process but drops its browser connection", which reads as if executors otherwise hold a live CDP connection that keeps the browser active and billed | live (KB1): touched browsers, including one whose REPL held `connectOverCDP`, idled out on time | Users and agents suspect executors of keeping browsers billing and add workarounds | State on the standby page that executor and REPL connections inside the VM do not count as activity |
| F9 | capability | No way to have browsers created through an MCP session deleted when that session or client goes away, and no default idle timeout per MCP connection; the only automatic close is each browser's own `timeout_seconds` | live (KB4) and source (`browsers.ts:990` is the only delete) | Agents that crash or forget leave browsers holding concurrency slots; every client has to build its own sweeper (this plugin's hooks) | An opt-in "delete my browsers when this MCP session ends" setting, or default tags plus a default timeout per API key or project |

What worked well: `wait` on `manage_auth_connections` long-polls and tells the model not to ask the user for progress; `execute_playwright_code` executors make parallel tabs simple; `list` with `tags` makes per-session cleanup reliable; tool results carry useful `next_actions`.
